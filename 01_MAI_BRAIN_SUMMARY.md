# MAI BRAIN
## Master summary and scope
Version: 1.0 | 22 November 2026 | Status: BUILD SPECIFICATION, NOT IMPLEMENTED SOFTWARE

MAI is the user's ML model/brain-inspired assistant. This package consolidates the useful NEXUS design principles into MAI without claiming that MAI is already trained, deployed, conscious, or generally intelligent. It does not assume MAI replaces NEXUS unless the owner decides so.

## Deliverable contract
Exactly five summary files in one folder named MAI BRAIN. No experimental data, model weights, or working assistant is bundled. Tool names in this package are proposed dependencies, not claims that they are installed. Nothing has been written into the user's original TOLBIT repository.

## Mission
A powerful terminal-native assistant that operates on the owner's knowledge base, maintains durable task state, retrieves evidence, reasons, predicts, uses approved tools, and improves through tested changes. Prefer local inference and storage; cloud services are optional and require explicit authorization for private data.

## Operating loop
Input -> validate -> retrieve -> load relevant memory -> plan -> check policy -> propose tool action -> approve if needed -> execute -> verify -> respond with sources -> record outcome and checkpoint.

## Required capabilities
| Capability | Implementation target | Evidence of success |
|---|---|---|
| Sensing | Text/files first; optional images, audio, sensors | Validated input schemas and units |
| Actions | Read/search/calculate; later approved writes | Correct tool calls; no unauthorized changes |
| Goals/reward | Task acceptance criteria and verified feedback | Measured task success, not flattering answers |
| Learning | Reviewed memory updates, optional supervised adapters/policy training | Improvement on untouched evaluation tasks |
| Memory | Working, episodic, semantic, procedural, tasks | Cross-session recovery and correction tests |
| Prediction | Dedicated temporal model where data supports it | Beats persistence on future-held-out data |
| Evaluation | Baselines, ablations, safety, speed and cost | Reproducible reports |

## Research is built in
Literature search, claim auditing, experiment design, code inspection, data analysis, and publication drafting are MAI core functions. Do not create a separate research brain or field brain. Domain packs: Maize, Energy, Health, Retail, ERP. Shared runtime, isolated data/permissions, domain-specific tools and evaluation. A module called a brain is still software; naming does not demonstrate cognition.

## What to reuse from TOLBIT
Consciousness/RG writings -> hypothesis archive and critical review. Energy case studies and results -> engineering knowledge with caveats. Simulation scripts -> inspectable tools, never automatically executed. D4 decoder -> optional telemetry experiment. Residual-inheritance reports -> research evidence requiring provenance review. Commercial files -> restricted product/planning references. Do not merge all statements into a single authoritative truth source.

## Important corrections carried forward
The older mini-brain is not evidence of consciousness or learned memory. Versions must not be pooled. v3.2 size caps cannot be inverted; boundary events can be censored; positive occupancy is not propagation; exact-one branching can be a detector artifact. v5 copied a snapshot rather than trained memory. No verified commercial advantage for the lattice or D4 is assumed. Larger models and more modules do not guarantee better judgment.

## Ownership
Keep original code, configurations, data, keys, backups, and deployment accounts under owner control. Third-party dependencies/model weights remain governed by their licenses; owning MAI does not confer exclusive ownership of them. Dataset rights, contributor agreements, model licenses, and trademark availability require review before sale. Do not promise legally exclusive ownership of AI-generated material.
